# 菜谱推荐小程序前端

## 简介

这是一个基于微信小程序开发的菜谱推荐应用，用户可以选择自己喜欢的食材或已有的食材，系统会自动推荐适合的菜谱。

## 功能特点

- 食材选择：用户可以选择多个食材，系统会根据食材匹配度推荐菜谱
- 搜索功能：支持搜索食材和菜谱
- 轮播图推荐：展示热门菜谱、时令推荐或专题菜谱
- 菜谱详情：展示菜谱的详细信息，包括食材、制作步骤、营养成分和推荐视频/网页

## 页面结构

### 首页 (index)
- 搜索栏：用于搜索食材或菜谱
- 轮播图：展示热门或推荐菜谱
- 食材选择区：展示可选的食材
- 已选食材区：显示用户已选择的食材
- 推荐菜谱列表：根据用户选择的食材推荐菜谱

### 菜谱详情页 (recipeDetail)
- 菜谱基本信息：名称、描述、图片
- 营养成分：热量、蛋白质、脂肪、碳水化合物
- 食材清单：所需的食材及用量
- 制作步骤：详细的制作流程
- 外部链接：推荐的视频和网页链接

### 外部链接页 (webview)
- 用于展示外部网页内容

## 技术实现

- 使用微信小程序原生开发
- 前端使用WXML、WXSS、JavaScript
- 后端使用Go语言，数据库使用MySQL

## 如何运行

1. 使用微信开发者工具打开项目
2. 确保后端服务已启动（默认地址：http://localhost:8080）
3. 点击编译运行

## 开发注意事项

- 请确保网络请求中的URL与后端服务地址一致
- 需要在小程序后台添加相关域名到安全域名列表
- 如需调试，可在微信开发者工具中开启不校验合法域名选项

菜谱推荐小程序：
用于给用户选择食材进行菜谱的推荐。

前后端分离，后端用go+mysql，本地数据库
前端用微信小程序开发里的js模板

要求：一.菜谱推荐页面：
1最顶部有搜索栏，针对食材和菜谱进行搜索，展示的菜谱和推荐菜谱用一个框区域。
2.该页面一开始有一个轮播图：轮播推荐区（展示热门菜谱、时令推荐或专题菜谱（如 "夏季清爽菜"、"减脂餐"）；
3.首页先展示可以选择的一些基本食材，如胡萝卜，牛肉，鸡蛋等，用户可以点击他想吃的食材或者现在已经有了的食材后，会自动推荐出适合做的菜谱列表，用户在菜谱列表里点击后进入菜谱页面。
补充：菜谱推荐的匹配算法，根据食材匹配度进行排列，用户输入的三个食材，与推荐菜谱里的所有菜全都一致，最优先推荐。

二.菜谱展示页面：
1.用户在推荐页面选择的菜谱后，跳转至这个页面展示，可以看到菜谱的名称，菜谱里包括的食材，耗时，制作流程（精细化，食材量和调味料都要有合理的g数），营养含量，推荐的网页和视频用于帮助用户制作。

菜谱推荐小程序整体框架设计
一、前端设计（微信小程序）
（一）页面结构
菜谱推荐页面
搜索栏
位于页面最顶部，用户可以输入食材名称或菜谱名称进行搜索。
搜索结果展示在页面下方的菜谱列表区域，与推荐菜谱一起显示。
轮播图
展示热门菜谱、时令推荐或专题菜谱等内容。
轮播图下方可以设置简单的文字介绍，吸引用户点击进入查看详细菜谱。
基本食材展示区
以图片和文字的形式展示一些常见的基本食材，如胡萝卜、牛肉、鸡蛋等。
每个食材图片可以设置点击事件，用户点击后将食材添加到已选食材列表。
已选食材列表显示在页面的某个区域，方便用户查看和管理。
菜谱推荐列表
根据用户输入的食材或搜索结果，展示匹配的菜谱。
菜谱以卡片形式展示，包括菜谱名称、食材图片、简短介绍等信息。
点击菜谱卡片，跳转到菜谱展示页面。
菜谱展示页面
菜谱名称
明显展示在页面顶部。
食材列表
列出制作该菜谱所需的所有食材，包括食材名称、用量（以 g 为单位）和调味料等。
制作流程
以步骤的形式详细展示制作过程，每个步骤可以包含文字说明和对应的图片（如果有）。
步骤顺序清晰，方便用户按照流程操作。
营养含量
展示该菜谱的营养成分，如热量、蛋白质、脂肪、碳水化合物等的含量。
推荐网页和视频
提供链接或嵌入视频，帮助用户更直观地学习制作过程。
网页链接可以打开小程序内置浏览器查看，视频可以使用小程序的视频组件播放。
（二）技术实现
页面布局
使用微信小程序的 WXML 文件进行页面结构的搭建，利用 flex 布局等实现良好的页面布局效果。
对于轮播图，使用小程序的 swiper 组件来实现。
菜谱推荐列表和搜索结果列表可以使用 view 组件结合循环渲染来展示。
样式设计
在 WXSS 文件中定义页面的样式，包括字体大小、颜色、间距等，保证页面美观、简洁且符合微信小程序的设计规范。
为不同状态的元素（如选中的食材、搜索结果高亮等）设置合适的样式，增强用户体验。
交互逻辑
使用 JavaScript 文件来处理页面的交互逻辑。
搜索栏的搜索功能通过调用后端接口，将用户输入的关键词发送到后端，获取搜索结果并更新页面的菜谱列表。
点击食材图片添加到已选食材列表，可以通过修改页面数据来实现，并将已选食材信息存储在本地缓存或发送到后端进行后续的菜谱推荐。
点击菜谱卡片跳转到菜谱展示页面，可以通过小程序的页面跳转 API 实现，并将菜谱的 ID 或相关信息作为参数传递到目标页面。
二、后端设计（Go + MySQL）
（一）数据库设计
食材表（ingredients）
字段：
id（主键，自增）
name（食材名称，唯一）
description（食材描述，可选）
菜谱表（recipes）
字段：
id（主键，自增）
name（菜谱名称）
description（菜谱简介）
image_url（菜谱图片的 URL）
video_url（推荐视频的 URL，可选）
webpage_url（推荐网页的 URL，可选）
菜谱食材关联表（recipe_ingredients）
字段：
recipe_id（外键，关联菜谱表）
ingredient_id（外键，关联食材表）
quantity（食材用量，以 g 为单位）
菜谱制作步骤表（recipe_steps）
字段：
recipe_id（外键，关联菜谱表）
step_number（步骤编号）
description（步骤描述）
image_url（步骤图片的 URL，可选）
菜谱营养含量表（recipe_nutrition）
字段：
recipe_id（外键，关联菜谱表）
calories（热量）
protein（蛋白质含量）
fat（脂肪含量）
carbohydrates（碳水化合物含量）
（二）接口设计
搜索接口
功能：根据用户输入的关键词搜索食材和菜谱。
请求方式：GET
请求路径：/api/search
请求参数：
keyword（搜索关键词）
返回数据：
包含搜索到的食材和菜谱信息，如食材名称、菜谱名称、简介、图片等。
菜谱推荐接口
功能：根据用户提供的食材列表推荐菜谱。
请求方式：POST
请求路径：/api/recommend
请求参数：
ingredients（用户选择的食材列表，以数组形式传递食材 ID）
返回数据：
推荐的菜谱列表，按照食材匹配度排序。每个菜谱包括名称、图片、简介等信息。
菜谱详情接口
功能：获取某个菜谱的详细信息。
请求方式：GET
请求路径：/api/recipes/{recipe_id}
返回数据：
菜谱的名称、食材列表（包括食材名称、用量）、制作步骤（包括步骤描述、图片）、营养含量（热量、蛋白质等）、推荐网页和视频链接等。
（三）业务逻辑实现
搜索逻辑
在 MySQL 数据库中，分别对食材表和菜谱表进行模糊查询，根据关键词匹配食材名称和菜谱名称等字段。
将查询到的食材和菜谱信息整合后返回给前端。
菜谱推荐逻辑
接收到用户提供的食材列表后，从菜谱食材关联表中查询包含这些食材的菜谱。
根据匹配算法，优先推荐与用户输入食材完全一致的菜谱，然后是包含大部分食材的菜谱，以此类推。
对推荐结果进行排序并返回给前端。
菜谱详情逻辑
根据传入的菜谱 ID，从菜谱表中获取菜谱基本信息。
从菜谱食材关联表中获取该菜谱的所有食材及其用量。
从菜谱制作步骤表中获取制作步骤的详细信息。
从菜谱营养含量表中获取营养成分信息。
将所有这些信息整合后返回给前端。
（四）技术选型
Go 语言
用于构建后端服务，处理 HTTP 请求、业务逻辑和与数据库的交互。
利用 Go 的并发特性和高效的性能，保证后端服务的稳定运行。
MySQL 数据库
作为本地数据库，存储食材、菜谱等数据。
通过 SQL 语句进行数据的查询、插入、更新和删除操作，满足后端业务逻辑的数据存储需求。
